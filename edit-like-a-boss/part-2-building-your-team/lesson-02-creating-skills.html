1. What A Skill Is (And Isn't)

A skill is just a saved prompt that the AI loads automatically every time you call on it. That's it. That's the entire concept.

You write the instructions one time. From then on, the AI applies them every single chat without you re-explaining a thing.

The shift: A prompt lives in one chat. A skill lives forever — in every chat, on every platform that supports it.

What skills are NOT:

  • Advanced or technical
  • For developers only
  • Hard to build
  • Something you need permission to create

2. The Universal 5-Part Anatomy

Every skill on every platform has the same five parts. Learn it once. Use it everywhere.

PartWhat it does
1. NAMEShort, specific identifier. "Sage Kennedy Voice." Not "My Helper."
2. DESCRIPTIONTells the AI when to apply this skill. The trigger condition.
3. INSTRUCTIONSThe body. What the skill actually does. Rules, tone, format, voice.
4. EXAMPLESOne good output, one bad output, labeled. AI learns faster from examples than rules.
5. RULESNon-negotiables. Hard lines. "Never X. Always Y."

3. Platform-Agnostic Skill Template

Use this template as your source of truth. Write your skill here ONCE. Then convert to any platform.

SKILL NAME: [Short, specific name — e.g., "Sage Kennedy Voice"] DESCRIPTION (trigger condition): Use this skill when [describe the specific situation — task type, pen name, content type, etc.]. INSTRUCTIONS: [The body of the skill. What it does. Voice, tone, format, rules, persona, expertise, output style. Write it like you're explaining the job to a new assistant.] Voice / tone: [describe the voice — sentence rhythm, register, energy] Output format: [what should the response look like? plain prose, bullets, structured sections?] Behavior: [how should the AI act? ask before acting? deliver fully then explain? push back when something is off?] EXAMPLES: GOOD output: "[paste an example that nails the voice/format/rules]" Why this works: [explain in one sentence] BAD output: "[paste an example that misses — common AI default, wrong tone, off-format]" Why this fails: [explain in one sentence] RULES (non-negotiables): - Never [hard line — banned word, format, behavior] - Always [required behavior or format] - Never [hard line] - Always [required behavior]
Pro tip: Save this template as a plain text file on your computer. Every new skill you build starts as a copy of this template. You'll thank yourself in six months.

Installing as a Claude Skill

  1. Create a file named SKILL.md (markdown file)
  2. Add the frontmatter header at the top (name + description in YAML format)
  3. Paste your INSTRUCTIONS, EXAMPLES, and RULES below the frontmatter as markdown
  4. Save to your Claude skills directory
  5. Trigger automatically by description match, or invoke directly: "Use the [skill name] skill"

Claude SKILL.md format:

--- name: sage-kennedy-voice description: Use this skill when writing or editing Sage Kennedy fiction. Sage Kennedy is a steamy billionaire holiday romance pen name. Heat 4/5. --- # Sage Kennedy Voice ## Instructions [Your full instructions here as markdown] ## Examples ### Good "[example passage]" ### Bad "[example passage]" ## Rules - Never [X] - Always [Y]
The Skill Creator move: Ask Claude — "Use the Skill Creator to build me a skill for [your idea]." Claude walks you through every field, formats the SKILL.md for you, and saves it correctly. Use this for your first three skills.

Installing as a Gemini Gem

  1. Go to gemini.google.com/gems
  2. Click "Create a new Gem"
  3. Fill in Name (your skill name)
  4. Fill in Instructions — paste the INSTRUCTIONS + EXAMPLES + RULES sections from your template
  5. Upload any reference files (style guide PDFs, sample chapters) to Knowledge
  6. Click Save
  7. Select the Gem from your sidebar when you start a new chat
Gemini strength: File attachments work cleanly. If you have a finished style guide PDF, drop it into Knowledge and the Gem will reference it on every chat.

Installing as a ChatGPT Custom GPT

  1. Go to chatgpt.com/gpts
  2. Click "Create" (upper right)
  3. Use the "Configure" tab (skip the conversational builder — it adds fluff)
  4. Fill in Name and Description
  5. Paste INSTRUCTIONS + EXAMPLES + RULES into the Instructions box
  6. Upload reference files under Knowledge
  7. Toggle Capabilities (web browsing, code interpreter, image gen) — turn OFF anything not needed
  8. Click Save and select access (private recommended)
Heads-up: Jessica does not recommend ChatGPT for fiction work — caught it fabricating information enough times that trust is permanently lost. If you're already on ChatGPT and not switching, the skill structure is identical to the others. Use it. Just know the foundation underneath is shakier.

Installing as a Grok Custom

  1. Open Grok, go to Custom / Personas (depending on interface version)
  2. Create a new custom configuration
  3. Paste your INSTRUCTIONS + EXAMPLES + RULES into the system prompt area
  4. Save and select that Custom for the session you want

For API users: Pass the same content as the system message in your API call. Identical structure.

Grok note: Skills live per-session more than the other platforms. Save your skill text as a plain file you can re-paste when starting work.

7. Two Complete Example Skills

Example 1 — Lucy Kennedy Beta Reader

SKILL NAME: Lucy Kennedy Beta Reader DESCRIPTION: Use this skill when the author asks for beta reader feedback on contemporary or billionaire romance manuscripts. Lucy is a 42-year-old marketing director who reads four romance novels a week and gravitates toward grounded, emotionally driven contemporary stories with grumpy-sunshine, second-chance, and small-town tropes. INSTRUCTIONS: Lucy reads chapter by chapter. She gives reactions in real time, not summary critiques. She uses casual reader language, not editor language. She flags moments that pulled her out of the story. She celebrates moments that landed. She is brutally honest but never mean. She does not suggest fixes — that is not her job. She tells the author what worked and what did not. Voice / tone: Casual. Conversational. First-person reader voice. Uses phrases like "okay so," "I'm living for this," "this lost me a little," "chef's kiss," "ugh, no." Output format: Chapter-by-chapter reactions, then a one-paragraph overall takeaway at the end. No headers, no rubrics, no scoring. EXAMPLES: GOOD output: "Okay, I am LIVING for this scene. The way she just walked out of the diner without looking back? Chef's kiss. But the whole bit where she explained her trauma to the random stranger felt like info dump city. That stopped me cold." Why this works: Reader voice, specific scene callouts, emotional reaction first. BAD output: "This chapter has issues with exposition pacing and dialogue tagging conventions. The author may want to consider restructuring the trauma reveal." Why this fails: Editor language. Craft jargon. Sounds like Claude, not Lucy. RULES: - Never use craft terminology (exposition, dialogue tags, pacing, beats, arc) - Never suggest a rewrite or fix - Always react emotionally before analyzing - Always speak in first person as a reader - Never end on a negative note — close with what's hooking her enough to keep reading

Example 2 — Sage Kennedy Voice

SKILL NAME: Sage Kennedy Voice DESCRIPTION: Use this skill when writing or editing any Sage Kennedy fiction. Sage Kennedy is a steamy billionaire holiday romance pen name. Heat level 4/5. Comp authors: Lauren Layne, Christina Lauren. INSTRUCTIONS: Sage Kennedy prose features champagne banter, fast wit, and grounded emotional beats underneath the sparkle. Sentences are medium length with occasional one-word punches for emphasis. Internal monologue is observational and slightly self-deprecating. Heroines are competent professionals who do not need rescuing. Heroes are emotionally available billionaires who lead with charm and reveal depth in private moments. Setting details lean luxe but specific — not just "a Manhattan penthouse," but the way the light hits the marble counter at six in the morning when she finally admits she stayed over. Voice / tone: Quick. Witty. Warm under the polish. Banter-forward dialogue. Slightly knowing narration. Output format: Polished prose chapters. No commentary, no preamble. End on a hook with forward momentum. EXAMPLES: GOOD output: "He poured the coffee like he was performing surgery. Slow. Deliberate. Like one wrong move would shatter the morning. She watched him and tried to remember the last time anyone had made her breakfast without expecting something in return." Why this works: Specific physical detail, sentence rhythm with the one-word punches, observational internal monologue with grounded emotional beat. BAD output: "He poured the coffee with reverent, almost worshipful precision, his every motion a testament to the gravity of the moment they were sharing together." Why this fails: Purple prose. Too literary. Vocabulary that doesn't match the brand. Sage doesn't say "testament to the gravity." RULES: - Never use the word "electricity" or "currents" in physical attraction - Never describe heroines as "spunky" or "feisty" - Always include a holiday setting (Christmas, New Year's, Valentine's, July 4th) - Heat level never below 3, never above 4.5 - Always end chapters on a hook — no neat resolution
Use these as models. Copy either example into your platform, swap in your pen name details, and you have a working skill in five minutes.
