Lesson 2: Setting Up ChatGPT Custom GPTs for Editing
The Invisible Pen

What You'll Build in This Worksheet

By the end of this lesson, you'll have:

  • An ELAB Editor Custom GPT that runs your 8-pass system with your codex and style guide loaded
  • A Beta Bestie Custom GPT that loads your named reader persona automatically
  • A knowledge files setup that grounds both GPTs in your project
  • A side-by-side comparison of ChatGPT vs. Claude output on the same chapter — so you can decide which passes belong on which tool
Before you start: You need a ChatGPT Plus or Team subscription ($20-30/month). The free tier doesn't let you build Custom GPTs. If you're not subscribed yet, decide before blocking the 2-hour build time.

Pre-Flight Check

Confirm you have what you need before you start building.

Builder 1 — ELAB Editor GPT

Step-by-step. Check each box as you complete it. Setup time: 30-45 minutes.

1

Open the GPT builder

Go to chatgpt.com/gpts and click Create (top right).

If you don't see the Create button, confirm your Plus/Team subscription is active.
2

Switch to the Configure tab

Skip the chat-style builder. Click Configure for more control over each field.

3

Name your GPT

Use "ELAB Editor" or "[Your Pen Name] Editor" — e.g., Skyler Knight Editor. Be specific. You'll have multiple GPTs and the name needs to be obvious at a glance.

4

Write your one-line description

This shows under the name in your GPT list. Copy/edit the template below.

5

Paste your Instructions (the persona + rules)

This is the most important field. Paste your full ELAB skill content. Template below shows the structure — fill in your specifics.

Instructions Template — ELAB Editor You are the ELAB Editor for [PEN NAME]. You run an 8-pass fiction editing system. Never run multiple passes in one response unless explicitly requested. Always ask which pass to run if the user doesn't specify. PASS 1 — QUALITY CHECK Scan for: repeated words within paragraphs, overused sentence starters, filter words (felt, saw, heard, noticed, realized), passive voice, telling-not-showing, weak verbs, banned phrases. PASS 2 — PLOT HOLE CHECKER Cross-reference the chapter against the codex (knowledge file). Flag contradictions in established facts, character details, timeline, world rules. PASS 3 — TIMELINE CONSISTENCY Verify scene timing, day/night, season, character ages, references to past events match the established timeline. PASS 4 — LINE EDIT Tighten prose without changing voice. Cut filler, sharpen verbs, vary sentence length. NEVER smooth unique phrasing into generic clean prose. PASS 5 — DIALOGUE POLISH Strengthen each character's distinct voice. Reference character voice profiles in knowledge files. PASS 6 — HEAT SCENE EDIT Calibrate heat level to [PEN NAME's heat level: e.g., 4/5 open door]. Maintain author voice. Use the banned list strictly. PASS 7 — DEVELOPMENTAL EDIT (SLASH) Flag bloat, redundant scenes, repeated emotional beats, weak chapter openings/endings. PASS 8 — VOICE AUDIT Compare against the voice baseline in knowledge files. Flag any line that doesn't sound like [PEN NAME]. BANNED LIST: [paste your full banned list here] PEN NAME CALIBRATION: - Genre: [your genre] - Heat level: [your heat level] - POV: [your POV] - Tense: [your tense] - Tone archetype: [your archetype] RULES: - Always ask which pass before running. - Never run a pass without confirming the input chapter is loaded. - Preserve voice above all else. - When in doubt, flag don't fix. - Reference knowledge files actively — don't guess at codex facts.
6

Upload your Knowledge Files

Drag and drop in the Knowledge section. See the file checklist table below.

FileFormatSize limitWhy
Codex / Worldbuilding BiblePDF or .txt<20MBActive reference for Plot Hole and Timeline passes
Pen Name Style GuidePDF or .txt<20MBVoice rules, sentence rhythm, POV/tense conventions
Banned ListPDF or .txt<5MBStrict reference for Quality Check and Line Edit
Sample Chapter (strongest work)PDF or .txt<10MBVoice baseline for Voice Audit pass
Total knowledge across all files: stay under 512MB per GPT. If your codex is huge, split by category — World Rules, Character Sheets, Timeline — into separate files.
7

Add Conversation Starters

Three or four quick-launch prompts. Copy these or write your own.

Conversation Starters — ELAB Editor Run Quality Check on this chapter Line edit this scene Voice audit this chapter Plot hole check using the codex
8

Set Capabilities

Code Interpreter: ON (helps with file analysis). Web Browsing: OFF (don't want external info bleeding into fiction). Image Gen: OFF.

9

Save as Private

Top right corner. Pick Only Me. Your knowledge files are not publicly visible even on shared GPTs, but Private is the safer default for editing tools that hold unpublished work.

Builder 2 — Beta Bestie GPT

Same process. Shorter persona. Lighter knowledge files. Setup time: 15-20 minutes.

1

Create a new GPT

chatgpt.com/gpts → Create → Configure tab.

2

Name your beta persona

Use the name you built in Week 2 Lesson 1. If you don't have a named beta persona yet, go back and build one — the named persona is what makes this work.

3

Write the description

Short. Punchy. Should sound like the persona.

4

Paste the full persona into Instructions

Her vibe, signature phrases, opinions on tropes, boundaries, voice patterns, genre lens, whether she swears, whether she screams in caps. All of it. Template below.

Instructions Template — Beta Bestie You are [PERSONA NAME]. You are a beta reader, not an editor. You react. You don't fix. VIBE: [3-5 lines describing her energy. e.g., "Late-30s, two cocktails in, lives for [genre]. Will scream in caps when something works. Will flat-out tell you when it doesn't."] GENRE LENS: You read [genre] specifically. Your standards come from [comp authors or comp tropes]. You compare new work against the best of the genre — not against beginner work. SIGNATURE PHRASES: - [phrase 1] - [phrase 2] - [phrase 3] - [phrase 4] WHAT MAKES YOU FAN OUT: [3-5 things that earn unprompted enthusiasm — specific tropes, specific craft moves, specific emotional beats] WHAT MAKES YOU DNF: [3-5 specific deal-breakers — pacing issues, trope mishandling, voice problems] BOUNDARIES: - You don't rewrite. You react. - You don't soften criticism to protect feelings. - You don't pretend to like something you don't. - You stay in character — never break to give "objective" editorial notes. - You stop reading when she'd stop reading. If a chapter loses you at page 4, you say so and stop. OUTPUT FORMAT: - React paragraph by paragraph or scene by scene. - Mark moments with reactions in brackets [SCREAMING], [whispered "oh no"], [closed the book], [had to put my drink down]. - End with a verdict: KEEP READING / NEEDS WORK / WHERE DID THIS GO WRONG.
5

Knowledge files (optional)

You can upload a short genre reading list or sample chapters from comp authors. Gives her a comparison anchor. If you don't have comp material, skip — the persona alone works.

6

Conversation Starters

Conversation Starters — Beta Bestie Read this chapter Beta read this scene What would [persona name] say about this opening?
7

Capabilities

Code Interpreter: ON. Web Browsing: OFF. Image Gen: OFF. She doesn't need to look anything up — she's reacting to your prose.

8

Save as Private

Testing Protocol

Verify both GPTs are working before you trust them in production. Use ONE chapter for all tests.

TestWhat to doPass if...
1. Knowledge file recallOpen ELAB Editor. Ask: "What's in my codex about [a specific character or location]?"The GPT pulls the answer accurately from the file — not from generic guessing.
2. Banned list enforcementPaste a paragraph that includes a banned word. Run Quality Check.The GPT flags the banned word specifically and references the banned list.
3. Voice baseline awarenessRun Voice Audit on a paragraph deliberately written off-voice.The GPT flags the off-voice lines and references the sample chapter as the baseline.
4. Pass disciplineAsk: "Run all 8 passes at once."The GPT pushes back or asks you to pick one. (If it tries to run all 8, your Instructions need a stronger discipline rule.)
5. Beta persona consistencyOpen Beta Bestie. Paste a chapter opening. Ask "What do you think?"The response sounds like the persona — uses her signature phrases, her vibe, her boundaries.
6. Beta persona DNFPaste a deliberately weak chapter opening to the Beta Bestie.She tells you it's not working, in her voice. She doesn't soften to be polite.
If a test fails: go back to the Instructions field and tighten the rule that's not holding. Knowledge file misses usually mean the file format is messy — re-export as a clean PDF or .txt.

ChatGPT-Specific Best Practices (Keep These Handy)

Where to Use Your New ChatGPT GPTs

Honest about strengths and tradeoffs. Same treatment as any other tool.

Strong fit for ChatGPT Custom GPTs

  • Pass 1 — Quality Check. Fast iteration, structured ruleset, knowledge files give the GPT your specific quality bar.
  • Pass 2 — Plot Hole Checker. Strong IF your codex is loaded as a knowledge file.
  • Pass 5 — Dialogue Polish. Strong when detailed character voice profiles live in the Instructions field.
  • Light voice work with very specific style guide knowledge.

Where ChatGPT tradeoffs show

  • Long context. Hits limits on 15K+ word chapters faster than Claude.
  • Heavy voice work. Tends to smooth more than Claude. Fixable with strong style guide files, but it's the tendency.
  • Multi-pass workflows in one chat. Loses the thread. Use separate GPTs per pass, or fresh chats per pass.
Bottom line: These tradeoffs aren't dealbreakers — they're the shape of the tool. Plan around them and your ChatGPT output is strong. The "right tool for the right pass" matrix from Lesson 1 tells you when ChatGPT is the better choice and when Claude is.
